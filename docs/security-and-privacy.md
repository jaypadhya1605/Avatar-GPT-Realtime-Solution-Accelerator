# Security and privacy

This accelerator is a synthetic training demonstration. It is not a medical device, clinical decision-support system, care-delivery channel, or system of record.

> [!WARNING]
> Do not enter protected health information, personally identifiable information, credentials, confidential customer data, or real patient details. The application has no content-level PHI detector and its visitor cookie is not user authentication.

## Data inventory

| Data | Source | Default handling |
| --- | --- | --- |
| Synthetic scenarios and grounding records | Versioned JSON in `data/` | Packaged with the app; scenario-isolated retrieval |
| Synthetic portraits | Three PNG files with manifest hashes and provenance | Served from the same origin; locally animated |
| Microphone audio | Browser user | Streamed through App Service to Voice Live; not intentionally persisted |
| Transcripts | Voice Live events | Held in browser memory for the active session and report; not sent to telemetry or persisted by default |
| Evaluation | Deterministic local rules | Computed from bounded transcript and interaction evidence; not generated by an LLM |
| Operational telemetry | App Service and OpenTelemetry | Request/dependency/exception metadata only; transcript and audio bodies are not intentionally logged |
| Custom Photo Avatar media | Optional Limited Access Preview | WebRTC media from Azure to browser; tenant character names remain server settings |

Review Azure service data processing and retention terms for the region and subscription before any production adaptation.

## Identity and secrets

- App Service uses a system-assigned managed identity and `DefaultAzureCredential`.
- The identity receives `Cognitive Services User` and `Foundry User` on the Foundry account.
- It receives `Monitoring Metrics Publisher` on Application Insights for Entra-authenticated ingestion.
- Local authentication is disabled on both Foundry and Application Insights.
- FTP and SCM basic publishing credentials are disabled.
- No API key, client secret, browser token, connection-string credential, or signed media URL is required by the baseline.

Application Insights still supplies a connection string as a non-secret routing identifier; Entra authorization protects ingestion.

## Browser boundary

The browser cannot choose or receive the Azure endpoint, model, prompt, voice, character, or credential. FastAPI enforces:

- strict same-origin WebSocket checks;
- an HTTP-only, SameSite visitor cookie;
- bounded start messages, audio chunks, SDP, and ICE fields;
- one active session per visitor plus visitor/network start limits;
- a 15-minute default session maximum;
- generic client errors while detailed service failures remain server-side;
- CSP, frame denial, no-referrer, MIME protection, and a microphone-only Permissions Policy.

Visitor identity is an abuse-control mechanism, not a sign-in system. Add enterprise authentication and authorization before using private content or controlled audiences.

## Synthetic grounding

The retriever loads only the checked-in corpus, validates its schema and digest, rejects unknown scenario IDs, filters by scenario before ranking, and returns at most three records. It does not call a vector database, browse external content, or retrieve records from another scenario.

## Persistence

`PERSIST_RESULTS=false` is the deployment default. The browser's save call therefore returns `saved: false` and no Storage account is provisioned.

The retained code supports a bring-your-own Blob extension. If enabled, it writes only the validated `SanitizedResultRequest`: pseudonymous visitor hash, timestamps, scenario/difficulty, aggregate latency, rubric/category scores, confidence, and coaching template IDs. It excludes transcript text, audio, avatar video, names, email addresses, and free-form notes.

Before enabling it, provision a private-governed Storage account and container, assign the web app identity `Storage Blob Data Contributor` at the narrowest practical scope, configure `AZURE_STORAGE_ACCOUNT_URL` and `AZURE_RESULT_CONTAINER`, set a lifecycle policy, document retention, and complete a privacy/security review. Do not use account keys or connection strings.

## Telemetry and logging

Do not add transcript, prompt, SDP, ICE credential, audio, or character-name values to logs. Treat correlation IDs, network-derived limiter keys, and pseudonymous identifiers as operational data. Keep Application Insights access least-privileged and follow organizational retention policy.

## Public baseline limitations

- App Service and Foundry public network access are enabled.
- The B1 plan is single-instance and not zone redundant.
- Rate limiting is in process memory and is not coordinated across instances.
- There is no WAF, private endpoint, VNet integration, tenant sign-in, or content filter for user-entered PHI.
- Preview avatar media depends on browser and enterprise WebRTC policy.

These choices keep the accelerator reproducible and inexpensive for workshops. They are explicit architecture decisions, not a production security posture.

## Publication controls

`scripts/privacy-scan.ps1` blocks known customer/deployment identifiers, private keys, storage keys, signed URL query parameters, likely client secrets, and all JPEG files. The asset validator allows only the three manifest-pinned PNG portraits. These checks reduce accidental publication risk but do not replace human review.

Report suspected vulnerabilities privately as described in [`SECURITY.md`](../SECURITY.md). Do not include secrets, personal data, or exploit details in a public issue.
